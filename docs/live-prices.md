# Маршрут и актуальность цены

## Что реализовано

Детали поездки показывают отдельные карточки «Туда» и «Обратно». Полный маршрут задаётся `outbound_segments` / `inbound_segments`: аэропорты, местные зоны, фактические моменты вылета и прилёта, оператор (`operating_airline`), продавец/маркетинговая авиакомпания (`marketing_airline`), номер рейса. Из этих сегментов рассчитывается ожидание пересадки и выявляется смена аэропорта. Переход местной даты обозначен как вылет в другой день: он сам по себе не доказывает ночную пересадку.

Демонстрационные маршруты и операторы условные и помечены DEMO. LIVE из Data API пока передаёт только общую авиакомпанию найденной цены и количество пересадок. Интерфейс явно сообщает, что города пересадок и операторы неизвестны; обратный перевозчик не выводится из авиакомпании рейса туда.

В карточках, деталях и избранном показано `received_at` в часовом поясе устройства. Это время получения данных нашим сервером, а не момент проверки мест авиакомпанией.

Контракт поддерживает `availability` (`available`, `unavailable`, `unknown`) и `expires_at`. Backend и клиент исключают явно недоступные и истёкшие предложения из результатов; в сохранённом снимке переход отключён. Неизвестная доступность остаётся неизвестной и не считается подтверждённой. Текущий Data API этих статусов не предоставляет, поэтому подготовленный фильтр пока не гарантирует скрытие распроданных билетов в LIVE.

## Как получать свежие цены

Надёжный путь — два этапа:

1. Недорогой кешированный поиск направлений для обзора месяца и бюджета.
2. По выбору конкретного маршрута и дат — живой поиск с деталями сегментов и тарифа. Перед переходом к покупке — повторная проверка конкретного предложения: обновить цену, показать изменение пользователю; при явной недоступности исключить вариант. При таймауте сохранить снимок как непроверенный, не объявлять билет распроданным.

Проверять следует тот же маршрут, рейсы, даты, пассажиров, валюту и багаж. Предложение другого поставщика нельзя подменять ценой Aviasales и обещать её по старой ссылке. Даже проверенное предложение может исчезнуть после проверки.

Уменьшение нашего TTL или обход нашего кеша обновляет только получение из кеша поставщика. Оно не создаёт сведения о местах. Автоматический сбор страниц Aviasales и обход ограничений API не являются способом подтверждения цены.

## Доступ к источнику

- [Travelpayouts Data API / Search API](https://travelpayouts.github.io/slate/): Data API работает с кешем. Для Search API нужна отдельная заявка и соблюдение условий: поиск инициирует пользователь, ссылки покупки получают по нажатию, автоматический сбор запрещён. Подключение фонового мониторинга к этому API нужно отдельно согласовать с поставщиком.
- [Duffel Offers](https://duffel.com/docs/api/offers): есть сегменты, фактический оператор, срок действия и обновление предложения. Нужны учётная запись, подходящий доступ и проверка покрытия наших маршрутов. Нельзя считать цену Duffel ценой на Aviasales.

Доступа к живому источнику в текущей конфигурации нет. Токены хранятся только на backend, не в чате и не в iOS-приложении. Интеграция и реальная проверка распродажи требуют этого доступа.
