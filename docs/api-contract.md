# Контракт Aviator v1

POST /api/v1/search: JSON `{ "origin": "SVO", "month": "2026-10", "max_budget_minor": 2500000, "direct_only": false }`.
Для всех аэропортов города добавьте `"origin_city_code": "MOW"`; `origin` остаётся аэропортом этого города для проверки справочника и локального месяца. Несовпадение города и аэропорта — 422. Без поля или при null поиск ограничен указанным аэропортом.
Аэропорт из GET /api/v1/airports; месяц вылета — текущий и следующие пять в зоне аэропорта. Бюджет 500000…50000000 копеек, целое; граница включительна. Валюта только RUB, один взрослый, туда-обратно. Класс тарифа Data API не гарантирует; внешний поиск открывается для эконом-класса.

Необязательные параметры:
- `departure_date`, `return_date`: обе строки `YYYY-MM-DD` или обе null. `month` соответствует месяцу вылета. Даты проверяются календарно, возврат позже вылета на 1–60 дней; может попасть в следующий месяц/год. Дата вылета не прошедшая в зоне отправления. Режим конкретных дат не ограничен выходными. Источнику передаются точные `departure_at` и `return_at`, клиент и сервер повторно проверяют даты в зоне соответствующего аэропорта.
- `weekend_only`: bool, по умолчанию true; для месяца оставляет пятница–воскресенье, пятница–понедельник, суббота–понедельник. false сохраняет остальные поездки. При точных датах игнорируется.
- `force_refresh`: bool, по умолчанию false. Обходит готовый локальный кеш backend для данного ключа; одновременные запросы разделяют одну загрузку. Не меняет кешированную природу внешнего источника.
- `destination`: аэропорт назначения, необязательный; `destination_city_code`: все аэропорты города назначения. Проверка соответствия справочнику как для origin; отправление и назначение не могут быть одним городом.

Ответ: `{ "offers": [...], "received_at": "ISO8601 UTC", "incomplete": false, "warnings": [] }`.
Предложение: `id` (стабильный маршрут/даты/рейс/источник, без цены), `city_code`, `city`, `country_code`, `country`, `origin_airport`, `origin_city_code` (код города вылета), `destination_airport`, `origin_city`, `origin_name`, `destination_name`, `departure_at`, `return_at` (ISO8601 с offset), `origin_timezone`, `destination_timezone`, `transfers`, `return_transfers`, `duration_to`, `duration_back` (минуты), `airline` (код по данным источника), `airline_name` (имя из локального справочника), `flight_number` (рейс туда), `price_minor` (целые копейки), `currency` = RUB, `search_url`, `partner_url`, `source` = LIVE/MOCK, `received_at`.
Неизвестные необязательные значения — null. Отправления отображаются в зоне соответствующего аэропорта. Получение ответа не является временем обнаружения цены. Нет вымышленных found_at/expires_at. Клиент по умолчанию сохраняет все варианты. Один лучший вариант на город — дополнительный фильтр, применяется после остальных фильтров и сортировки. Время прибытия рассчитывается из отправления и положительной длительности плеча, отображается в зоне аэропорта назначения. Длительность null/0 не считается известным прилётом. Полей operating carrier/багажа/возвратности источник не гарантирует.

Кеш исходной выдачи отделён от бюджета/прямых рейсов/выходных: источник запрашивается с пересадками и верхней границей 500 000 ₽, затем пользовательские ограничения применяются при каждом чтении кеша. В ключ входят origin/город origin, month, обе точные даты, destination/город destination, рынок и валюта. Ошибки не кешируются. Идентификатор предложения не зависит от цены; варианты разных дат/рейсов не склеиваются.

GET /health: `{ "status": "ok", "live_configured": false }`.
GET /api/v1/airports: массив объектов `iata, city_code, city, name, country_code, country, timezone` из локального снимка официального справочника.

Ошибка: `{ "error": { "code": "configuration|upstream_auth|upstream_http|upstream_json|upstream_failure|timeout|validation|rate_limit", "message": "русский текст" } }`. Статусы: 503 конфигурация; 502 источник; 504 timeout; 422 входные данные; 429 ограничение с Retry-After. Частично прочитанные страницы возвращаются с incomplete и причиной. Ошибка первой страницы никогда не становится пустым успехом.

## Региональные поездки

Необязательное поле `region`: `any` (по умолчанию), `europe`, `usa`. Неизвестное значение — 422. Конкретный `destination` должен принадлежать выбранному региону; несовпадение — 422. Европа: европейские страны без РФ/Беларуси, включая Турцию и Кипр; США: country_code US.

Без destination региональный поиск собирает отдельные запросы по 24 европейским / 12 американским городам (`backend/app/regions.py`). Не более четырёх запросов одновременно, две страницы по 100 записей на город, общий предел 20 секунд. Кеш разделён по региону; смена бюджета/прямых/выходных использует ту же исходную выборку. Частичные результаты сохраняются при ошибках отдельных городов; при отсутствии любых успешных ответов возвращается ошибка. Региональная подборка всегда `incomplete=true`: её ограничения указаны в warnings. Цена сортируется по возрастанию на сервере; приложение также поддерживает убывание и другие порядки.

## Пакетный поиск

POST `/api/v1/search/batch`: `{ "queries": [<SearchRequest>, ...] }`, от 1 до 7 запросов с теми же полями и проверками, что обычный поиск. Ответ `{ "results": [{ "result": <SearchResponse>, "error": null }, { "result": null, "error": "русский текст" }] }` сохраняет порядок запросов. Ошибка отдельного поиска не уничтожает успешные ответы остальных. Некорректный пакет целиком возвращает 422; ограничение частоты — 429.

Пакет считается одним пользовательским действием в лимитере, внутри одновременно выполняются максимум два поиска. Соседние даты используют до семи пар дат, избранное объединяет одинаковые маршруты/даты и разбивает обновление на пакеты. Поля первоначальной цены и результата обновления принадлежат локальному хранилищу клиента, а не ответу поставщика.
