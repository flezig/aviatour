# Работа двух участников с Codex

## Общая доска

Владелец: `flezig`. Репозиторий: `flezig/aviatour`.
Название доски: `Aviatour — Tasks`.
Номер: **1**. URL: https://github.com/users/flezig/projects/1.

GitHub Issues хранят содержание задачи, комментарии — решения и точки продолжения, Project — статус, приоритет, объём и тип. На одну задачу создаётся один issue. Участники работают под собственными GitHub-аккаунтами.

## Подключение участника

1. Владелец приглашает друга в репозиторий через Settings → Collaborators и отдельно даёт Write-доступ к Project через настройки доступа доски. Доступ к репозиторию сам по себе не даёт права редактировать личный Project.
2. Друг принимает приглашения и клонирует репозиторий:

   ```sh
   git clone https://github.com/flezig/aviatour.git
   cd aviatour
   ```

3. На каждом компьютере установить GitHub CLI и войти под своим аккаунтом:

   ```sh
   brew install gh
   gh auth login --hostname github.com --git-protocol https --web
   gh auth refresh --hostname github.com -s project
   gh auth status
   ```

   Команда установки выше предназначена для macOS с Homebrew. Для другой ОС используйте [официальную установку GitHub CLI](https://cli.github.com/).

4. Открыть локальную папку в Codex. Общие инструкции находятся в корневом `AGENTS.md` и передаются через Git вместе с проектом.

## Доска и статусы

| Status | Значение |
| --- | --- |
| Backlog | Идея или задача на будущее |
| Todo | Можно брать в работу |
| In Progress | Есть исполнитель и рабочая ветка |
| Review | Результат готов, PR ожидает проверки/слияния |
| Done | Результат принят, issue закрыт |

Поля: Priority — High / Medium / Low; Effort — Small / Medium / Large; Task Type — Feature / Bug / Research (название Type зарезервировано GitHub). Представления: Board (по Status), Quick wins (High + Small, незавершённые), Research backlog (Research + Backlog).

Для автоматического Done включить встроенный workflow Project «Item closed» → Done. Новые issues агент добавляет в Project при создании; закрытие issue с кодом происходит после слияния PR с `Closes #N`.

## Работа без конфликтов

Перед началом читать issue с комментариями и проверять исполнителя. Одна активная задача — один ответственный. Второму участнику выбирать другую задачу или явно согласованную подзадачу. Отдельная задача — отдельная ветка и PR. Основная ветка `main` содержит принятые изменения.

Не смешивать чужую работу со своей и не перезаписывать историю веток. Если оба меняют одни файлы, зафиксировать порядок работы в issue. Перед продолжением получить актуальные изменения с GitHub.

## Комментарий для продолжения

```text
Сделано:
Решения и причины:
Ветка / коммит / PR:
Проверки и результаты:
Осталось / препятствия:
Следующий шаг:
```

## Если нет доступа к GitHub

Проверить `gh auth status`. Если авторизация отсутствует, участник входит самостоятельно; пароль или токен в чат отправлять не нужно. Отчёт временно сохранить в `docs/handoffs/`, а после восстановления доступа перенести в issue. Локальный отчёт сам по себе не обновляет общую доску.
