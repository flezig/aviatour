# Сайт и партнёрские ссылки — 12.10.2026

Сделано:
- Каталог `web/`: сайт в оформлении приложения на существующем backend. Поиск (откуда, регион или направление, месяц или точные даты, короткие выходные, бюджет, прямые рейсы), выдача с быстрыми фильтрами и сортировками, карточка поездки с маршрутом и временем на месте, переход на Aviasales. Страницы «Как мы зарабатываем», «О проекте», источники фотографий. Без сборки и зависимостей.
- `GET /go?u=<search_url>` в backend: принимает только HTTPS-ссылку поиска Aviasales и перенаправляет на партнёрскую ссылку Travelpayouts, а при её отсутствии — на исходную.
- Партнёрские ссылки создаются официальным API Travelpayouts (`links/v1/create`), когда в backend/.env заданы `TRAVELPAYOUTS_MARKER` и `TRAVELPAYOUTS_TRS`. Результат кешируется на сутки; ошибка открывает обычную ссылку и приостанавливает попытки на 60 секунд.
- Backend отдаёт `web/` по корневому адресу и сжимает ответы gzip (справочник аэропортов: 590 КБ → 92 КБ).
- `scripts/build_web_assets.py` готовит фотографии сайта из каталога приложения (30 городов и hero, 2,8 МБ) и копирует атрибуцию.

Решения и причины:
- Переход идёт через собственный адрес, а не через запрос из браузера с последующим открытием вкладки: обычная ссылка `target="_blank"` не блокируется браузером и работает без JS-обработчиков.
- Партнёрская ссылка создаётся в момент перехода, а не для каждого предложения в выдаче: в выдаче до тысяч предложений, а API принимает 10 ссылок за запрос.
- Запрашивается длинная ссылка (`shorten=false`): её домен tp.media уже разрешён в приложении iOS. Короткий tp.st принят только на стороне backend.
- На сайте по умолчанию включён фильтр «Один вариант на город»: без него первые 60 карточек регионального поиска занимает один город. «Все» показывает каждую дату и рейс.
- Выбор аэропорта на сайте скрывает 66 записей справочника с кириллическими кодами: поиск принимает только три латинские буквы и отвечает на них 422. В приложении iOS они по-прежнему доступны для выбора.
- Блок «Кто мы» скрыт, пока в `web/site.js` нет имён и контактов: выдуманных данных на странице нет.
- Утверждение на странице «Как мы зарабатываем» о комиссии «около 1 %» взято со страницы программы Aviasales в Travelpayouts (1,1–1,3 % от цены билета) на 12.10.2026.

Размещение — 12.10.2026:
- Сайт и backend размещены на Vercel: https://aviatour.vercel.app, проект `aviatour` в команде `vavilons-projects` (тариф Hobby), функция в регионе fra1. Публикация выполнена из рабочей папки командой `npx vercel deploy --prod --yes`; с GitHub проект не связан, поэтому новые изменения сами не публикуются.
- `pyproject.toml` задаёт точку входа `backend.app.main:app` и серверные зависимости, `vercel.json` — тип проекта FastAPI и регион, `.vercelignore` — список разрешённого к загрузке: только `backend/app`, `web`, `pyproject.toml`, `vercel.json` (64 файла). `backend/.env` и остальной репозиторий на сервер не попадают.
- Файлы сайта Vercel отдаёт с CDN, запросы `/api/v1/*`, `/go`, `/health` идут в функцию. Без `"framework": "fastapi"` в vercel.json сборка ничего не делает и сайт отвечает 404.
- Проверено на опубликованном адресе: страницы и фотографии открываются, справочник аэропортов и проверка входных данных работают, `/go` перенаправляет на Aviasales и отклоняет чужие адреса, `/.env`, `/backend/.env`, исходники и README недоступны.
- В Vercel задано `RATE_LIMIT_REQUESTS_PER_MINUTE=60` вместо локальных 10: общий лимит на процесс иначе блокировал бы посетителей. Лимит и кеш по-прежнему у каждого экземпляра функции свои.
- Токен Travelpayouts в Vercel добавляет владелец аккаунта. Пока его нет, поиск на сайте отвечает «LIVE не настроен»; после добавления нужна повторная публикация.
- Правила Vercel разрешают тариф Hobby только для некоммерческого использования; сайт, зарабатывающий на партнёрских ссылках, под них не подходит. Для проверки годится, для запуска с комиссией нужен платный тариф или другой хостинг.

Данные — редакционные гиды приложения по 25 городам: `scripts/build_web_assets.py` копирует нужные поля из `backend/app/city_guides.json` в `web/data/city-guides.json`. Для остальных городов блока нет.

Измерение — 12.10.2026:
- Токен, ID партнёра (788655) и ID проекта (584314) одного аккаунта Travelpayouts заданы в backend/.env и в Vercel. Реальный API партнёрских ссылок проверен: `/go` на опубликованном сайте перенаправляет на tp.media с этими ID и исходным адресом поиска. Появление перехода в отчётах кабинета ещё не проверено.
- `/go` принимает метку перехода `s` (строчные латинские буквы, цифры, дефис, до 32 символов) и передаёт её в Travelpayouts как sub_id. Сайт ставит метку `web`, а при включённом эксперименте — `web-home-a` / `web-home-b`.
- `web/config.js` — настройки сайта: эксперименты и блок «Кто мы». Эксперимент `home` (A — только форма, B — форма и варианты сразу) выключен, все видят B. Вариант выбирается один раз на браузер и хранится в localStorage; `#ab=A` или `#ab=B` в адресе показывает вариант без записи.
- Счётчика посещений по-прежнему нет: кабинет Яндекс Метрики 12.10.2026 был недоступен. Без него известны только переходы (по отчётам Travelpayouts), но не доля перешедших.

Осталось / препятствия:
- Появление перехода в отчётах кабинета Travelpayouts не проверено.
- Приложение iOS открывает обычную ссылку напрямую и комиссию не приносит.
- На сайт не перенесены избранное, сравнение, рейтинг городов, панель подробных фильтров и условия полного бюджета.
- Нет счётчика посещений и цели «переход на Aviasales» и заголовков безопасности. Доступность vercel.app у российских провайдеров без VPN не проверена.
- Safari и реальные телефоны не проверялись.
