# Команда Aviator в Paradev

Из папки tools/paradev задайте SUPERSET_WORKSPACE_ID для своего рабочего пространства или передайте --workspace ID. Для запуска нужен Codex CLI. Путь к нему можно указать в AVIATOR_CODEX_CLI. Готовые отчёты прежних запусков находятся в archive/.

Для текущей темы запустите в терминале этого пространства `python3 -B start-team.py`. Для другой темы передайте `--topic /путь/к/карточке.json`. Образец — [compare-pair.json](compare-pair.json). Укажите задачу, решение владельца и короткие отрывки источников для каждой роли. Строки проверяются по текущему коммиту HEAD. Для другой ревизии проверьте смысл выдержек. Код Aviator агенты только читают.

Исследователь готовит одну карточку. Аналитик и ревьюер независимо получают её. Редактор получает три заключения. Передача атомарная. При ошибке зависимый этап останавливается. Рабочая папка выдаётся командой `python3 -B paradev-run.py prepare`. Готовые выводы сохраняются по ролям в Markdown. Повторный запуск с той же темой, ревизией и версией обвязки использует сохранённые результаты. Блокировка этапа исключает два одновременных обращения к модели по одной и той же карточке.

## Контекст

Пакет исходников формируется один раз на ревизию и тему. Каждой роли передаются общие строки и её собственный фрагмент. У специалистов отдельные вопросы и короткие ответы. Редактор получает карточки коллег без журналов работы. Точечные обращения к Git предусмотрены для технического ревьюера. Веб-поиск, plugins и apps отключены. Стабильная часть инструкций идёт первой. Это повышает возможность переиспользовать совпадающий префикс; фактическую долю кеша показывает отчёт. [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

## Расход и остановка

| Роль | Модель и effort | Порог числа ответов модели | Порог новых входных + выходных токенов |
|---|---|---:|---:|
| Исследователь | Sol 6.2 High | 2 | 30 000 |
| Аналитик | Sol 6.2 xHigh | 2 | 35 000 |
| Ревьюер | Astra 6.2 High | 4 | 45 000 |
| Редактор | Sol 6.2 High | 2 | 35 000 |

После каждого опубликованного события расхода счётчик обновляет файл роли. При достижении порога обвязка позволяет завершить уже готовый ответ и останавливает продолжающийся процесс. Возможен перерасход за ответ, который уже выполняется. Ограничение времени работы одной модели — четыре минуты. При отсутствии первой телеметрии в течение 100 секунд процесс останавливается. Причина записывается в файл .error. Автоматической платной повторной попытки нет.

`python3 -B paradev-run.py report` показывает расход текущего набора карточек. Кешированные токены включены во входные, reasoning включён в выходные. Источник — журналы конкретных сессий Codex, повторные записи с тем же response_id отсеиваются. Пропущенная телеметрия обозначается прочерком. У перенесённых карточек в контрольном запуске пути к исходным заключениям записаны в reused.json. Исходный и контрольный прогоны собраны в [tokens.md](archive/initial/tokens.md).

## Обсуждение по короткой карточке

Для оценки вариантов интерфейса запустите `python3 -B start-team.py --discussion kazan-results.json` в каталоге харнесса. Для другой темы передайте JSON с вопросом, вариантами и проверенными фактами по этому образцу. Обычная команда сама ждёт завершения и возвращает одну квитанцию. После разрыва соединения укажите `--receipt ПАПКА`, чтобы получить результат существующего запуска.

Дизайнер и два судьи работают на Astra 6.2 xHigh. Каждый получает одну и ту же карточку объёмом до 2400 знаков и вопрос своей роли. Судьи формулируют собственное решение до знакомства с голосами коллег. Программа сохраняет три голоса, обоснования и расхождения. Результаты и измерения находятся в папке запуска. Полный вход, кешированный ввод, новый ввод и выход учитываются раздельно. Поле записи кеша заполняется, когда его возвращает Codex. Для расчёта общего объёма складываются вход и выход. При сравнении запусков также приводите новый вход плюс выход, число обращений, стоимость повторных попыток и отдельно расход основного чата.

## Повторная проверка направлений без длинного чата

Из этого пространства запустите `python3 -B start-team.py --check destinations`. Одна команда запускает координатор в Paradev, дожидается результата и возвращает короткую сводку. Координатор — обычная программа. Все HTTP-запросы, ожидание, сверка покрытия и проверки браузеров выполняются без обращений к модели. Два независимых специалиста на xhigh получают только свои результаты. Для запуска нужны ранее установленные браузеры Playwright и Node. При необходимости путь к установленному модулю можно указать в NODE_PATH.

Профиль воспроизводит условия ноябрьского замера: четыре российских города, декабрь 2026 — февраль 2027, 100 000 ₽, 1–14 ночей. Каждый новый запуск создаёт новую папку, выполняет 12 запросов «Азия» и 24 запроса по отдельным странам, сохраняет время получения цен и фактическое время проверки. Проверки браузеров сверяют исходный экран с эталонами предыдущего релиза, проверяют ввод, очистку, сохранение по ссылке и настоящие карточки городов. Перед проверкой на другой период обновите месяцы профиля.

В папке запуска находятся result.json, observations.json, журналы проверок и заключения специалистов. Для присоединения к запущенной проверке используйте `--receipt ПАПКА`. После ошибки `--retry-check ПАПКА` повторяет незавершённое ревью на уже собранной в течение часа матрице. При неполной матрице программа добирает только отсутствующие запросы в пределах часа. На ревью предусмотрена одна явная повторная попытка. Сводка включает расход предыдущей попытки. Никакие токены фонового координатора не начисляются. Внешний чат расходует токены на запуск и отчёт, его надо учитывать отдельно. Для обычных команд по теме start-team.py также дожидается результата. Прежний запуск без ожидания доступен с --detach.

При запуске из Codex в caller-overlap.json отдельно записываются завершённые обращения внешнего чата за интервал фоновой проверки. Параллельные задачи в том же чате входят в этот интервал. Вызов, который инициировал запуск, мог завершиться до начала замера. Полный ход или исторический срез можно посчитать с помощью `turn_usage.py ПУТЬ_К_ЖУРНАЛУ ID_ХОДА [--until ВРЕМЯ_UTC]`. Отсутствие измерений внешнего чата означает, что точный расход по нему неизвестен.
