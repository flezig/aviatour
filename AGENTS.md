# Совместная работа над Aviatour

Репозиторий: `flezig/aviatour`. Общая память команды — GitHub Issues и связанный GitHub Project. Личные чаты Codex не являются общей памятью. Пиши описания задач и отчёты по-русски.

## Перед началом задачи

1. Прочитай `README.md` и `docs/collaboration.md`, проверь состояние рабочей папки и актуальные ветки.
2. Если пользователь указал issue, прочитай описание, все комментарии и связанные PR: `gh issue view N --repo flezig/aviatour --comments`.
3. Для новой содержательной задачи проверь открытые issues, чтобы не создать дубликат. Создай issue с целью, контекстом, критериями готовности и планом, добавь его в общий Project. Запрос на работу в этом репозитории разрешает ведение относящихся к нему issues, комментариев, статусов и PR. Это не разрешает отправку личных сообщений или приглашений другим людям без указания пользователя.
4. До изменения кода проверь исполнителя, статус и последние комментарии. Если задачу уже выполняет другой участник, согласуй разделение с пользователем. Если она свободна, назначь текущего GitHub-пользователя, переведи в In Progress и оставь комментарий с веткой и областью работы. Повторно проверь issue: назначение не является атомарной блокировкой.
5. Работай в отдельной ветке `issue-N-short-description` от актуальной `origin/main`. Не перезаписывай чужие изменения и не делай force push.

## Во время работы и при передаче

- Записывай в issue существенные решения и их причины, препятствия, изменения плана. Не публикуй секреты и личные данные.
- Перед остановкой или передачей оставь комментарий: что сделано, ветка/коммит/PR, какие проверки выполнены и их результат, что осталось, точный следующий шаг.
- Сохраняй полезную историю: не заменяй комментарии других участников и не создавай вторую независимую «память» в локальных файлах.
- Если GitHub недоступен или нет авторизации, сообщи об этом. Подготовь отчёт локально в `docs/handoffs/`, затем перенеси его в issue после восстановления доступа. Не утверждай, что статус обновлён, пока это не проверено.

## Завершение

- Выполни проверки, соответствующие изменению. Если приложения или тестов ещё нет, укажи это явно.
- Создай PR с описанием результата, проверок и `Closes #N`; переведи задачу в Review. Прикрепи созданный PR к текущему чату средствами Codex, если они доступны.
- Слияние PR выполняй только по просьбе пользователя. До слияния не закрывай issue и не ставь Done.
- После слияния проверь закрытие issue и переведи карточку в Done. Для задачи без изменений кода закрой issue после выполнения её критериев готовности.

## Поля общей доски

Status: Backlog, Todo, In Progress, Review, Done.
Priority: High, Medium, Low. Effort: Small, Medium, Large.
Type: Feature, Bug, Research.

Номер и ссылка доски должны быть записаны в `docs/collaboration.md` после создания. Если их нет, сначала проверь существующие проекты владельца; не создавай дубликат.
